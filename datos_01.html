1 - Navegación y Búsqueda - Portales de Datos Abiertos y Estrategias de Captura.

Integración de Portales de Datos Abiertos y Arquitectura de Ingesta ETL

Historia

La evolución del acceso a la información pública ha transitado desde archivos físicos y solicitudes burocráticas hasta el movimiento Open Data iniciado formalmente a mediados de la década de 2000. Con el lanzamiento de plataformas como CKAN por la Open Knowledge Foundation y el portal Data.gov en 2009, se estandarizaron los formatos de intercambio. Originalmente, los ingenieros descargaban archivos estáticos (CSV, XML), pero el paradigma cambió hacia el consumo de flujos dinámicos. En el ecosistema de Microsoft, esta evolución culminó en la integración de Power Query (motor M) dentro de Excel, transformando la hoja de cálculo de un repositorio pasivo a una terminal de inteligencia de datos capaz de conectarse a repositorios globales en tiempo real mediante protocolos RESTful. Esta transición refleja la necesidad de democratizar el dato manteniendo la integridad estructural y la trazabilidad de la fuente original.

Descripción Formal

La captura de datos desde portales abiertos requiere un entendimiento profundo de los protocolos HTTP y la estructura de los objetos JSON/XML. En Excel, el proceso se formaliza mediante el motor de Power Query. La lógica algorítmica de ingesta sigue el patrón: Solicitud -> Autenticación -> Normalización -> Carga.

Para conectar un portal que utiliza una API REST, se emplea la función en lenguaje M: Json.Document(Web.Contents("https://api.datos.gob/v1/recurso")).

Desde la perspectiva de la hoja de cálculo, una vez que los datos son normalizados en una tabla, la navegación se realiza mediante referencias estructuradas. Por ejemplo, la sintaxis =TABLA_DATOS[[#Encabezados];[Columna_A]] permite una navegación dinámica que no depende de direcciones de celda estáticas (A1).

El algoritmo de búsqueda interna en grandes volúmenes de datos capturados debe optimizarse. Mientras que BUSCARV realiza una búsqueda lineal O(n), la implementación de BUSCARX (XLOOKUP) permite búsquedas binarias O(log n) si los datos están ordenados, utilizando el argumento de coincidencia exacta. Sintaxis: =BUSCARX(valor_buscado; matriz_busqueda; matriz_devuelta; [si_no_se_encuentra]; [modo_de_coincidencia]; [modo_de_busqueda]). El modo de búsqueda '2' habilita la búsqueda binaria, crucial para el rendimiento en datasets de ingeniería que superan las 100,000 filas.

Intuición

Imagina que los Portales de Datos Abiertos son bibliotecas infinitas donde los libros se actualizan solos cada segundo. Antes, para hacer un informe, tenías que ir, copiar a mano la información y llevarla a tu oficina. Si el libro cambiaba, tu informe quedaba obsoleto. Las estrategias de captura modernas actúan como 'tuberías inteligentes'. En lugar de copiar el contenido, conectas una tubería (Power Query) desde la biblioteca hasta tu hoja de Excel.

La navegación no se trata solo de encontrar una celda, sino de entender el esquema. La intuición detrás del uso de estas herramientas es pasar del 'dato como objeto estático' al 'dato como flujo'. Al usar funciones de búsqueda avanzada, no estás simplemente mirando una lista; estás interrogando a una base de datos local que sabe exactamente dónde reside cada atributo sin tener que leer toda la lista de arriba a abajo cada vez. Es la diferencia entre leer todo un diccionario para encontrar una palabra o usar el índice alfabético para saltar directamente a la sección correcta.

Aplicación

En el entorno de un ingeniero informático, esta competencia es vital para el desarrollo de Dashboards de monitoreo urbano o análisis de ciberseguridad. Por ejemplo, un ingeniero puede automatizar la captura de feeds de vulnerabilidades (CVE) desde portales de seguridad nacional para cruzarlos con el inventario de software de la empresa.

Otro caso crítico es la ingeniería ambiental, donde se consumen APIs de sensores meteorológicos en tiempo real para predecir fallos en infraestructuras. El uso de Excel como 'frontend' de datos permite a los ingenieros prototipar algoritmos de limpieza y validación de datos (Data Wrangling) mucho más rápido que escribiendo scripts de Python desde cero, facilitando la comunicación de hallazgos técnicos a gerencias no técnicas mediante tablas dinámicas conectadas directamente al origen de datos abierto.

Estrategias de Captura: Web Scraping Estructural y Conectores OData

Historia

El Web Scraping surgió como una necesidad técnica cuando la información valiosa residía en páginas HTML sin una API disponible. En los años 90, esto requería complejos scripts en Perl o C. Con la maduración de la web, surgieron estándares como OData (Open Data Protocol), impulsado por Microsoft en 2007, que busca crear un protocolo común para el consumo de APIs RESTful. Excel evolucionó para interpretar la estructura del DOM (Document Object Model) de las páginas web, permitiendo que usuarios técnicos identifiquen tablas dentro de etiquetas <table> sin escribir código. Esta capacidad de 'minería de superficies web' transformó a Excel en una herramienta de integración de datos heterogéneos, permitiendo capturar información de sitios que no fueron diseñados originalmente para compartir sus bases de datos de forma estructurada.

Descripción Formal

La captura avanzada se divide en dos vertientes: el consumo de servicios OData y el parsing de HTML.

  1. OData: Utiliza una sintaxis de consulta en la URL similar a SQL. En Excel, esto se gestiona mediante OData.Feed("url/service.svc"). Permite operaciones del lado del servidor como $filter, $select y $expand, reduciendo la carga de datos en la red.

  2. Web Scraping: Cuando se utiliza Web.Page(Web.Contents("url")), el motor de Excel analiza el árbol jerárquico del HTML. El ingeniero debe identificar la firma de la tabla deseada.

Lógica de Algoritmo para extracción de múltiples páginas (Pagination): Se requiere una función recursiva o un bucle de generación de listas: List.Generate(()=> 1, each _ <= MaxPages, each _ + 1, each "https://url.com?page=" & Number.ToText(_)).

En la hoja de cálculo, para manejar datos capturados que pueden contener errores de tipo, se utiliza la lógica de manejo de errores: =SI.ERROR(VALOR_BUSCADO; "Dato no disponible"). Para ingenieros, es fundamental la validación de tipos de datos (casting) mediante la función =VALOR() o =TEXTO(), asegurando que los identificadores capturados de la web coincidan con las claves primarias locales para permitir un 'JOIN' lógico mediante =FILTRAR() o =BUSCARX().

Intuición

Capturar datos de la web es como intentar extraer los ingredientes de un pastel después de que ya ha sido horneado. El 'Web Scraping' es el proceso de analizar la estructura del pastel (la página web) para separar la harina, el azúcar y los huevos (los datos). Por otro lado, un conector OData es como si el panadero te diera la receta y los ingredientes por separado de forma ordenada.

La estrategia de captura es fundamental porque define la 'frescura' de tu análisis. Si capturas mal, tu sistema de ingeniería basará sus decisiones en espejismos. La búsqueda aquí no es solo encontrar un valor, sino navegar por la jerarquía de la información: pasar de una etiqueta <div> a una fila <tr> y finalmente a la celda <td> que contiene el valor crítico. Es un ejercicio de ingeniería inversa sobre la interfaz de usuario para llegar a la capa de persistencia de datos.

Aplicación

Un ingeniero informático aplica estas estrategias en la consolidación de 'Threat Intelligence'. Puede programar Excel para que cada mañana realice un scraping de diversos foros de seguridad y blogs técnicos, normalice las tablas de indicadores de compromiso (IoC) y las compare contra los logs de tráfico de la red corporativa.

En la gestión de proyectos (DevOps), se pueden usar conectores OData para extraer métricas de Azure DevOps o Jira directamente a Excel. Esto permite realizar análisis de velocidad del equipo (Burn-down charts) personalizados que las herramientas estándar no ofrecen, facilitando el cálculo de desviaciones típicas en los tiempos de entrega de los sprints y la optimización de recursos humanos mediante modelos matemáticos aplicados sobre las tablas capturadas.

Navegación con Matrices Dinámicas y Algoritmos de Búsqueda No Lineal

Historia

Históricamente, la navegación en Excel era 'celda-céntrica'. Si una función devolvía múltiples valores, estos quedaban atrapados en una sola celda o requerían fórmulas de matriz (Ctrl+Shift+Enter) que eran difíciles de mantener y computacionalmente costosas. En 2018, Microsoft introdujo el motor de 'Matrices Dinámicas', un cambio fundamental en el núcleo de cálculo. Esto permitió que las funciones 'desbordaran' (spill) los resultados hacia celdas adyacentes de forma automática. Este cambio alineó a Excel con lenguajes de programación modernos como Python o R, donde las operaciones se realizan sobre vectores y matrices de forma nativa. Para el ingeniero, esto significó el fin de las búsquedas limitadas y el inicio de una era donde la navegación de datos se basa en la programación funcional dentro de la cuadrícula.

Descripción Formal

Las matrices dinámicas introducen una nueva semántica de navegación. El operador de rango desbordado # permite referenciar el resultado completo de una función de búsqueda.

Algoritmicamente, la función =FILTRAR(matriz; incluir; [si_vacio]) implementa una búsqueda de predicados sobre un array, devolviendo todos los registros que cumplen una condición booleana. Esto es equivalente a una cláusula WHERE en SQL.

Sintaxis avanzada: =LET(data; A2:B100; criterio; E1; FILTRAR(data; INDEX(data;;1)=criterio)). Aquí, la función LET se usa para definir variables, mejorando el rendimiento al evitar recálculos redundantes del mismo rango (optimizando la complejidad temporal).

Para navegación multidimensional, se utiliza =BUSCARX con múltiples criterios usando el operador de concatenación & o lógica booleana: =BUSCARX(1; (rango1=crit1)*(rango2=crit2); matriz_retorno). Esta última técnica utiliza multiplicación de matrices booleanas (0 y 1), donde el resultado 1 indica que todas las condiciones se cumplen, permitiendo una navegación precisa en datasets complejos donde una sola clave primaria no es suficiente para identificar un registro.

Intuición

Imagina que estás buscando a todos los estudiantes que sacaron más de 9 en un examen. En el Excel antiguo, tenías que ir fila por fila y, si encontrabas a uno, anotarlo en otra hoja. Si querías a todos, tenías que repetir el proceso muchas veces. Con las matrices dinámicas, simplemente gritas: '¡Todos los que tengan más de 9, den un paso al frente!'. Automáticamente, se crea una nueva lista a partir de ellos.

El símbolo # es como un lazo que agarra a todo ese grupo, sin importar si son 5 o 500 personas. Ya no buscas un dato, buscas comportamientos o subconjuntos de datos. La navegación deja de ser un 'mapa de coordenadas' para convertirse en un 'sistema de filtros inteligentes'. Entender esto es crucial para un ingeniero porque permite construir modelos de datos que se adaptan automáticamente al tamaño de la entrada, eliminando errores de 'rango fuera de límites'.
